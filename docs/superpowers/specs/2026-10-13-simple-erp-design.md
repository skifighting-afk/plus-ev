## 1. 기본 화면과 메뉴

PC는 넓은 화면을 활용하고 모바일은 세로로 배치한다. 모바일 방식으로 PC 모든 정보를 작은 화면 여러 장에 흩어놓지 않는다.

```text
매장 이름                         간편보기 | 자세히보기
오늘 날짜 · 영업 전 / 영업 중 / 마감 완료

오늘 매출             오늘 인건비             오늘 남은 돈
확정 / 마감 전         실제 · 미완료 N건         확정 / 집계 중

[매출 입력]            [근무 추가]             [금고 입출금]

확인할 일 N개          오늘 근무 · 근무 중 / 완료

이번 달: 실제 인건비 / 예정 인건비 / 예상 남은 돈

홈 · 매출 · 근무 · 직원 · 더보기
```

- 오늘 매출이 없으면 `마감 전`으로 표시하며 0원 매출로 확정하지 않는다.
- 실제 인건비는 완료된 근무에서만 계산한다. 출근 중·퇴근 누락을 0원으로 처리하지 않는다.
- 필요한 비용이 미입력됐으면 남은 돈을 확정값처럼 표시하지 않는다. 카드에 `집계 중`, `예상` 등의 상태를 붙인다.
- 급여 총액과 현금 잔액은 서로 다른 개념으로 표시한다. 대표 인출은 손익을 줄이지 않는다.
- 자주 쓰는 행동은 별도의 화면 꾸미기를 거치지 않고 바로 접근한다.
- 모바일에서 터치 버튼은 충분한 크기를 확보하며 가로 넘침을 막는다. PC에서도 주요 메뉴를 숨겨 탐색 단계를 늘리지 않는다.
- 교육·홍보·장터·가입 혜택·고급 분석은 더보기나 관련 상세 화면에 남긴다.
- PRO 홍보는 기본 홈에서 여러 카드로 반복하지 않는다. 일반 이용자는 분석 진입 시 설명·요금 안내를 보고 PRO 이용자는 기존 기능으로 들어간다.

## 2. 매출·금고

- 오픈은 시재와 오픈 버튼만 먼저 보여준다. 전일 실제 마감 현금이 있으면 시재 후보로 제안하며 자동 확정하지 않는다.
- 매출 입력은 총매출·카드·이체 중심. 현금 매출은 차액으로 계산한다. 음수 현금은 오류를 표시하고 저장하지 않는다.
- 지폐별 장수는 `현금 세기`에 접어 둔다. 필수 입력과 고급 옵션을 구분한다.
- 이미 오픈·마감했다면 완료 요약과 수정 진입점으로 바꾼다. 수정 이력을 보존한다.
- 엔트리는 새 기본 입력에서 제외한다. 기존 행 수정 시 저장된 값을 보존한다.

금고에는 별도의 입출금 기록을 둔다. 비용 표에 대표 인출이나 이미 인건비로 계산한 지급액을 다시 넣지 않는다.

```text
예상 금고 현금
= 오픈 시재 + 현금 매출
  + 기타 금고 입금 − 현금 비용 지급
  − 대표 인출 − 현금 급여 지급
```

- 각 금고 사건은 금액·구분·사유·매장·영업일·실행자·발생 시각·연결 정산 ID를 가진다.
- 현금 비용 지급과 금고 출금이 같은 사건이면 한 번만 차감한다.
- 현금 급여 지급은 정산 기록과 금고 기록을 같은 트랜잭션으로 저장한다.
- 재시도·더블클릭은 같은 요청 ID로 처리해 출금을 중복 생성하지 않는다.
- 취소는 원본 삭제 대신 반대 기록을 남긴다. 급여 지급 취소와 금고 복구도 함께 처리한다.
- 과거 마감일 지급을 뒤늦게 추가하면 금고 대사 재확인이 필요하다고 표시한다. 이미 마감한 숫자를 조용히 바꾸지 않는다.
- 기존 현금 비용의 저장 의미를 서버 스키마와 마감 함수에서 먼저 확인하고, 중복 차감이 없도록 연결한다.

## 3. 근무·인건비

**스케줄은 예정, 완료된 출퇴근·직접 입력은 실제 근무**로 분리한다. 과거 급여와 실제 근무가 없던 달을 자동으로 재계산하지 않는다.

### 근무 추가

`직원 → 근무일 → 출근·퇴근 → 휴게 → 저장` 순서. 직원 선택 시 저장된 급여 조건을 적용한다. 직접 입력은 `수동 입력`과 작성자를 남긴다.

- 한국 시간 기준으로 저장·표시한다. 자정을 넘는 근무는 다음 날 퇴근으로 명시한다.
- 실제 시작·종료 시각을 저장하고, 기존의 영업일 구분과 일관되게 근무일을 지정한다.
- 휴게는 근무시간보다 작아야 하며 음수·잘못된 시간은 거부한다.
- 당일 출퇴근이 완료되면 오늘 인건비에도 즉시 반영한다. 기존 `어제까지` 집계와 혼동시키지 않는다.
- 장시간 근무·퇴근 누락·겹친 근무는 확인 대상으로 남기고 임의 추정해 확정하지 않는다.

### 중복·보정 규칙

- 스케줄과 실제 기록은 같은 날 각각 더해서 비용으로 잡지 않는다.
- QR 기록에서 생성한 실제 근무는 출근·퇴근 원본 ID를 연결해 중복 생성하지 않는다.
- 수동 근무가 있는 시간대에 QR 기록이 들어오면 자동 합산하지 않고 겹침 확인을 요청한다.
- 검증된 기록을 선택하거나 보정하여 실제 근무 한 건으로 확정한다. 선택·보정 이력을 남긴다.
- 여러 매장 소속 직원의 근무·출퇴근·급여는 회원 소속과 매장 ID로 구분한다.
- 확정된 급여 마감 월은 일반적인 수정에서 차단한다. 기존 해제 권한을 유지한다.
- QR·위치·활성 소속·명시적 출근/퇴근 검증을 유지한다.

### 계산·전환

- 새 실제 근무 계산과 기존 스케줄 예상 계산을 별도 함수로 제공한다.
- 기본급·야간·연장·주휴·공제 등은 기존 계약 설정을 따라 계산한다. 이 작업에서 계약 종류를 임의 변경하지 않는다.
- 실제 급여 계산에는 해당 근무 당시의 급여 조건을 보존해 이후 시급 변경으로 과거 지급액이 바뀌지 않게 한다.
- 주 단위 수당은 월 경계와 전월 근무를 포함해 기존 계산과 대조한다.
- 스케줄만 있는 과거 달은 `스케줄 기준`으로 유지한다. 실제 기록이 없어졌다는 이유로 급여를 0으로 덮어쓰지 않는다.
- 적용 시작일·집계 기준을 표시하고 실제 기준으로 전환한 기간만 새 계산을 사용한다.
- 직원 화면·사장님 급여 대장·CSV·명세서·월별 집계가 같은 계산 결과를 사용해야 한다.
- 월 예상은 확정 실제 근무와 남은 예정 근무를 날짜별로 조합하며 동일 근무를 중복 더하지 않는다.

## 4. 헬퍼

`이름 → 시급/일당 → 금액 → 날짜·시간·휴게 → 미지급/지급 완료`를 한 흐름으로 제공한다. 기존 헬퍼는 검색해 재사용하고 전화·계좌는 선택 정보로 둔다.

- 시급은 실제 유급 시간으로 계산한다.
- 일당은 약정된 일 급여 금액을 별도로 저장한다. 임의 시급 환산을 등록 조건으로 삼지 않는다.
- 일당의 기준 금액과 수당·공제를 구분해 표시한다. 기존 계약별 수당·공제 설정을 일당 선택만으로 끄지 않는다.
- 등록 시 예상 계산 내역과 지급 예정액을 보여줘 `일당 금액`과 `실수령액`을 혼동하지 않게 한다.
- 약정액·시간·급여 조건은 근무별로 남긴다. 다음 근무의 금액 변경이 이전 정산을 바꾸지 않는다.
- 미래 근무는 예정 인건비, 완료 근무는 실제 인건비에 반영한다.
- 지급 완료는 실제 계좌 송금 기능이 아닌 지급 사실 기록이다. 버튼·안내에 이를 명확히 쓴다.
- 현금/이체 지급 수단을 선택한다. 현금은 금고 출금과 연결하고 이체는 금고 현금을 차감하지 않는다.
- 급여 기록·근무 기록·지급 사실 중 하나만 저장되고 나머지가 실패하는 상태를 트랜잭션으로 막는다.
- 기존 월별 지급 표시와 새 근무별 지급 표시가 서로 모순되지 않게 이관·집계한다. 이미 지급한 금액은 새 미지급 목록에서 다시 요구하지 않는다.

## 6. 검증과 완료 조건

100개 항목은 화면 노출과 실제 동작을 확인한 뒤 완료 처리한다. 숨긴 기능의 접근 경로도 확인한다. 문서에 체크하는 것만으로 완료 처리하지 않는다.

- 기존 엔진·가입 혜택·긴급구인·무한지원·PRO·QR 테스트 유지.
- 기본 간편보기, 기존 선택 유지, 자세히보기 복귀, 권한별 메뉴 확인.
- 새 입력에서 엔트리 제외, 과거 값 보존 확인.
- 시급·일당·야간·월 경계·휴게·퇴근 누락·미래 근무·급여 마감 확인.
- QR/수동 중복·동시 요청·복수 매장·새로고침 재시도 확인.
- 현금/이체 지급, 대표 인출, 취소, 현금 비용 중복 차감 방지 확인.
- 일반/PRO/점장 제한/직원 화면에서 허용되지 않은 데이터와 행동이 노출되지 않는지 확인.
- 모바일·PC 화면 넘침, 버튼 식별, 기록 저장 후 상태 갱신 확인.
- 데모를 새 저장 구조와 일치시키고, 실제 업무 데이터에 가짜 지급·근무·출금을 만들어 테스트하지 않는다.
- 변경 SQL은 사전 트랜잭션 검증과 복구 전략을 함께 준비한다. 데이터가 생긴 새 테이블은 복구 시 삭제하지 않는다.

사용성 목표는 실제 사용으로 검증한다. 처음 쓰는 사장님이 안내 없이 `헬퍼 근무 추가 → 인건비 확인 → 매출 마감`을 완료하는지, 되돌아간 화면과 막힌 입력을 기록한다. 아직 검증하지 않은 성공률·소요 시간을 완료 성과로 주장하지 않는다.

## 7. 실행·복구 경계

명세 승인 후 화면 정리, 실제 근무·헬퍼 정산, 금고 연결, 통합 검증으로 구현 작업을 나눈 계획을 작성한다. 각 작업은 테스트 가능한 단위로 진행하며 마지막에는 전체 코드 검토와 실제 배포 확인을 수행한다.

소스 복구는 백업 커밋을 기준으로 한다. 실제 근무·금고 기록이 생긴 이후에는 소스만 되돌려도 과거 동작으로 완전히 복구된다고 주장하지 않는다. 새 데이터는 보존하며 호환 처리 또는 전용 되돌림 절차를 준비한다.

아직 수행하지 않은 작업: 제품 코드 변경, 데이터베이스 변경, 기존 업무 기록 변경, 배포. 사용자 승인 없이 실제 금전 송금·자동 계약 변경을 수행하지 않는다.
